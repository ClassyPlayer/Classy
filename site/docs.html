Wi-Fi

WebDAV Sync

Copies music from a WebDAV server (a Synology NAS, Nextcloud, or any other server that speaks WebDAV) to the player, so you can listen without a cable. The copy goes one way: from the server to the player. Classy never uploads, renames or deletes anything on the server.

Open it: Main menu → Settings → Library → WebDAV Sync. The row shows @ and the username, or Not Configured.

Set it up

  1. Server URL: the address of the folder that holds your music, for example https://192.168.1.10:5006/music. Everything below that folder can be synced. The address must start with http:// or https:// and have a host. An address with user:password@ in it is refused: put the login in the next two rows.
  2. Username and Password: type them with the keyboard screen.
  3. Test Connection checks the address and the login. It shows Connected, or why it could not connect.

Test Connection and Sync Now need Wi-Fi. When Wi-Fi is not connected, they open the Wi-Fi screen.

Set it up with a file

Typing a long address with the wheel is slow. Instead, put a file named classy_webdav.json in the top folder of the internal storage (the folder that holds Music), then open WebDAV Sync:

{ "url": "https://192.168.1.10:5006/music", "user": "name", "password": "secret" }
FieldValue
urlThe Server URL: http:// or https:// with a host.
userThe username. It must not be empty.
passwordThe password. It must not be empty.
  • WebDAV Sync reads the file, saves the settings and then deletes the file, so the password does not stay on the storage in plain text.
  • A file that is not valid is not imported and stays. The screen shows classy_webdav.json: invalid. Correct the file, or delete it by hand.
  • A valid file that Classy cannot delete is not imported either. The screen shows classy_webdav.json: cannot delete it, delete it by hand.
  • While a sync runs, the file stays. Classy imports it the next time you open WebDAV Sync.
  • A file with another address is a new Server URL: see Log Out / Reset.

A self-signed certificate (https)

A certificate that Android trusts (from a known authority, for the name in the Server URL) works with no step, also after it is renewed.

A NAS at home usually has a certificate that no authority signed. The first time you connect, Classy shows Certificate not trusted, and the WebDAV Sync screen gets a Certificate part: the SHA-256 fingerprint of the server certificate, in four lines of hex.

  1. Find the SHA-256 fingerprint of the certificate on your NAS, for example in the certificate details of a web browser.
  2. Compare all four lines with the lines on the player.
  3. If they are the same, choose Trust Certificate.
  • Classy then accepts that one certificate, with any host name (also a NAS that you reach by its IP address).
  • If the certificate changes (for example a renewal), the connection stops until you trust the new one. Compare the fingerprint again: the step looks the same as the first time.
  • Android 4.4 does not know some newer authorities, for example Let's Encrypt. Such a certificate also needs Trust Certificate, and again after each renewal.
  • A public certificate for another name also shows the Trust step.
  • A new Server URL forgets the trusted certificate.

http:// works too, but has no protection: the password goes in clear text with every request, also from Auto Sync on any Wi-Fi network that the player joins. Use https:// where the server has it.

Choose the folders

Folders shows how many folders you ticked. Open it to see the folders of the Server URL. The top row reminds you of the keys: Center: open · Hold: select.

  • Center opens a folder.
  • Hold Center ticks or unticks a folder. A tick shows at the left.
  • This Folder, the first row, ticks the folder that is open (push Center). Use it for a folder with only files, for example the folder of the Server URL itself.
  • The files of a folder show below its folders. You cannot tick one file.
  • Ticking a folder takes everything inside it. The folders inside show ticked, and you cannot untick them one by one. To leave one out, untick the parent and tick the folders that you want.
  • Ticking a parent replaces the ticks of the folders inside it.
  • Each time you open a folder, Classy lists it again, so changes on the server show.

The folders you tick are what the player keeps. The files of a folder that you untick are removed from the player at the next sync.

Sync

Sync Now lists the ticked folders, downloads the new and changed files, and deletes the files of the folders that you unticked. A screen shows the folder that it lists, then the files in progress, the percent and the speed. Back cancels the sync.

  • Every file in a ticked folder is copied, not only the audio files: covers and .lrc lyrics come too.
  • The files go to the Music folder of Save To, with the folder tree that they have below the Server URL. For example, …/music/Artist/Album/01.flac becomes Music/Artist/Album/01.flac.
  • A file is changed when its ETag on the server changed. If the server gives no ETag, Classy compares the size and the date.
  • Before it downloads, the sync checks the free space. If the files do not fit, it stops with Not enough space, the space it needs and the free space.
  • When a sync downloaded or deleted files, the library scans again, so the songs show up. This also occurs after a sync that failed or that you cancelled.
  • Parallel Downloads (1 to 4; Center goes to the next value): the files that download at the same time. 1 is the gentlest for a weak Wi-Fi or NAS, and it is the default.
  • Last Synced shows the time of the last sync that worked, or Never. After a sync that failed (also an Auto Sync), Last sync failed shows its error below it, until a sync works.
  • A song that is playing is never replaced or deleted. It waits for the next sync.
  • A sync never writes over a file that it did not make (your own files, or those of Jellyfin Sync). If such a file has the size of the server file, the sync takes it as that file and does not download it again (for example after Log Out / Reset). Else the server file is skipped, and your file stays as it is.
  • A download that fails or that you cancel leaves the old file as it was. It writes to a hidden .partial-….part file first; the next sync deletes such files that a stopped run left.
  • If no folder is ticked, Sync Now asks before it deletes all the files that it synced (No folder selected: the synced files will be deleted.). If it synced nothing yet, it shows Select folders first.

Save To: Internal or SD Card

  • Save To sets the storage: Internal or SD Card. SD Card needs a microSD card in the player (else SD card not found). You cannot change it while a sync runs.
  • After a change, Move Synced Files shows the number of synced files on the other storage. It asks, then moves them; nothing is downloaded again.
  • Until you move them, a sync leaves them where they are. Only a file that changed on the server downloads to the new place, and its old copy is deleted.
  • A move copies each file, checks it, and then deletes the old copy, so a failure or a cancel never loses a file. A file that is playing stays where it is: move again later. A file that is already at the new place is never written over; if it has the same bytes, only the old copy is deleted.
  • On the SD card (FAT), the characters < > : " | ? * \ in a name become _, and a name does not end with a dot or a space. Two names that become the same share one file.

Auto Sync

With Auto Sync On, the player syncs by itself when it is on Wi-Fi and charging, at most once an hour.

  • It starts when Wi-Fi connects or when you connect the charger. If the hour is not over yet, it tries again when the hour ends, while the player stays on Wi-Fi and charging.
  • A try that failed also counts for the hour, so a server that is off is not tried again and again.
  • It downloads, and deletes the files of unticked folders, as Sync Now does. When no folder is ticked, it never deletes all the synced files.
  • It has no progress screen, and you cannot cancel it. Its errors show under Last Synced.
  • It works only while the Classy app runs.

Files you deleted on the server

When a synced file is gone from the server, Classy does not delete your copy. It lists the file under Deleted on NAS, with the name of its folder, and you choose:

  • Push Center on a file to delete it, or choose Delete All (when the list has two files or more). Each delete asks first.
  • Your copy stays until you delete it. A file that comes back on the server leaves the list.
  • When a ticked folder is gone from the server, its files go to this list too. A listing that fails for another reason never marks files as deleted: the sync stops.

Log Out / Reset, or a new server

Log Out / Reset forgets all the WebDAV Sync settings: the address, the login, the certificate, the ticked folders, Auto Sync, Parallel Downloads, Save To and Last Synced.

  • The songs stay on the player. Classy forgets that it synced them, so no later sync deletes them. If you do not want them, delete them with a file manager.
  • If you set it up again and tick the same folders, a sync takes back each copy that has the server's size. From then on it is a synced file again (an untick deletes it).
  • A new Server URL does the same to the server settings: no ticked folders, no certificate, no Last Synced. The songs of the old address stay.
  • The local paths come from the folder of the address. A sync never writes over an old copy at such a path: it takes the copy back if it has the server's size, and else skips that file. Old copies that no new file takes back stay; delete them by hand.
  • Only the same address in another spelling (for example with a / at the end) keeps everything.
  • Both are refused while a sync runs (Syncing...). If the sync record cannot be saved, nothing changes and the screen shows Cannot save the sync record.

If something goes wrong

MessageWhat to do
Server unreachableIs the player on the correct Wi-Fi? Is the address correct, and the NAS on?
Check username/passwordThe server refused the login (HTTP 401 or 403).
Certificate not trustedCompare the fingerprint, then Trust Certificate (Certificates).
Not enough spaceThe message shows the space the sync needs and the free space. Free some space, or tick fewer folders.
HTTP 404 on a folderThe folder is gone from the server. In a sync, its files go to Deleted on NAS.
HTTP 301 (or another 3xx)The server sends Classy to another address. Classy does not follow it, so that the password goes to no other server. Use the final address as the Server URL.
SD card not foundSave To is SD Card, but there is no microSD card. Put the card in, or set Save To to Internal.
Cannot save the sync recordThe record of the synced files (webdav_ledger.json) could not be written, for example on a full storage. Nothing changed.
Too many folders (a loop on the server?)A ticked folder has more than 20,000 folders below it, or the server links back to a folder above.

Limits

  • One way only: no upload, and no two-way merge.
  • The check for a changed file uses the ETag and the date of the server, not a hash of the content.
  • Basic authentication only. The password is stored in plain text in the app's private settings (adb backup can copy them; the app allows backups). Clear Data or Log Out / Reset removes it.
  • All files go to the Music folder. To sync audiobooks, use Jellyfin Sync.
  • No partial resume: a cancelled download starts again.
  • A file that the sync skips (your own file at its place, with another size) shows only in the log, not on the screen.
  • A download has no total time limit: a very slow server keeps a sync running (you can cancel Sync Now, but not Auto Sync). The number of files has no limit; a ticked folder can have at most 20,000 folders.
  • The sync record is not flushed to the disk before its rename. After a power loss it can be lost: nothing is deleted then, but the synced files are no longer tracked.
  • Auto Sync works only while the app runs: a background job would need Android 5 (API 21), and the Y2 has Android 4.4.

For developers

The code is in app/src/main/java/com/themoon/y1/sync/webdav/ and controllers/sync/WebDavUiController.kt.

  • Files. WebDavSyncProvider: settings, ticked folders, one-time import of classy_webdav.json (WebDavConfigFile). WebDavClient: PROPFIND (Depth 1) and GET with OkHttp. CertPin: the trust manager. SyncPlan: pure functions for what to download, mark or delete, and the path mapping (no I/O except pruneEmptyDirs). WebDavSync: runs a sync or a move on one background thread and owns the ledger. AutoSyncGate, WebDavAutoSyncReceiver: when Auto Sync may start. WebDavErrors: errorText, the one-line message of an error.
  • Shared with Jellyfin Sync: the MediaSyncProvider interface, the SyncLedger file format, SyncLocks, the playing-file rule and the list model (Center opens, Hold ticks). The engine is its own (not SyncManager, which makes paths from Jellyfin metadata): WebDAV Sync copies the folder tree of the server as it is, keyed by path.
  • Prefs webdav_sync: url, user, password, pin, dest_sd, auto_sync, parallel, ticked (a set of hrefs), last_sync, last_auto_attempt, last_error (empty after a sync that worked).
  • Ledger webdav_ledger.json in the primary storage root, one item for each synced file, keyed by its percent-encoded href. LedgerItem keeps the Jellyfin names: jellyfinId = href, libraryId = the ticked folder it was found under (can go stale: coverage is by path, isUnder), localPath, fileSize, serverDateModified = "<etag>|<lastModified>", orphaned. Item type music.
  • Listing. Sub-folders are walked breadth first, one PROPFIND each, with a visited set and MAX_FOLDERS = 20,000. An answer is read into memory (at most 8 MB, checked before each write; at most 120 s for a listing; cancellable) and refused if its bytes have <!DOCTYPE (Android's parser ignores disallow-doctype-decl). A root that is not DAV:multistatus is an error, not an empty folder. A failed status inside the 207 is an error: DavHttpException for the folder itself (404 = gone), DavEntryRefused for an entry (the sync stops, nothing is marked deleted). Properties come only from 2xx propstat blocks. A 404 on a ticked folder is an empty list; on a sub-folder it skips that sub-folder; another error stops the sync.
  • Requests. Basic auth on every request. urlFor refuses an absolute href of another host; redirects are not followed (a 3xx is an error). A relative href must start with /; an absolute href of this server becomes its path. hrefs compare percent-encoded; decodeHref decodes each segment as UTF-8 (+ stays +). Timeouts: 10 s connect, 30 s read.
  • Download. GET with Accept-Encoding: identity into a new .partial-*.part file (exclusive create) next to the target. Never more bytes than the listing or the Content-Length gave; with no size, it stops 64 MB before the storage is full. Then mayReplace (no while the target plays: TargetBusy) and replaceFile, one rename. On FAT the old file moves aside to <name>.old (.old1, …) first, and back if the new one cannot move in.
  • Certificates. PinningTrustManager(pin, systemTrustManager, host): the pinned leaf (SHA-256) passes with any host name; else a chain that Android trusts passes if its leaf names the host (OkHostnameVerifier); else CertNotTrusted(fingerprint). The host check is in the trust manager, so the client's HostnameVerifier accepts all. WebDavSyncProvider.changeUrl clears the pin.
  • Plan (SyncPlan.build): downloads (with replaces for a recorded copy at another path), adopt and conflicts (a file at the target that the ledger does not record), orphan, unorphan and remove (not covered by a ticked folder, unless the file is also a target). remove runs only with a ticked folder or the user's confirmation (removeAllUnticked; Auto Sync never sets it). Downloads run on a pool of parallel threads; the first error stops the others. The ledger is saved every 20 files and in a finally.
  • Deletes. deleteTracked and the delete of a replaced copy touch only files below the Music folders (canonical paths), skip a playing file, remove only the record when another record keeps the same file, and then call pruneEmptyDirs up to the Music roots.
  • One run at a time: isRunning, a single-thread executor and launch. forgetAll (Log Out / Reset, another server) takes the same lock and saves an empty ledger before it changes the settings; if the save fails (LedgerNotSaved), nothing changes. SyncLocks.hold keeps a partial wake lock and a Wi-Fi lock (Classy:WebDavSync), with a 6-hour cap.
  • Auto Sync. AutoSyncGate.shouldRun is a pure function; lastCounted ignores a stored time after now (the clock was set back). The recheck at the end of the hour is a Handler.postDelayed. ClassyApplication.onCreate registers the receiver in code for CONNECTIVITY_ACTION and ACTION_POWER_CONNECTED. It is not in the manifest: on Android 4.4 a manifest receiver for a connectivity change starts a second process of the app, and stopStaleProcesses then stopped the running launcher.
  • UI. WebDavLevel: Root, Folders(href), Orphans. Folder rows are RowLook.CHOICE (onClick opens, onHold ticks). The progress screen updates at most 4 times a second and smooths the speed. A new text needs all seven language packs (scripts/check_translations.py --strict).
  • Tests in app/src/test/java/com/themoon/y1/sync/webdav/: SyncPlanTest, WebDavClientTest, AutoSyncGateTest, CertPinTest, WebDavConfigFileTest, WebDavErrorsTest.

Audiobooks

Audiobook Series Cover Flow

An optional Cover Flow for audiobooks, made from your folders: one cover for each series, and one cover for each book in it.

Turn it on

  1. Main menu → Settings → Library → Audiobook Series Cover Flow (first row of Library): push Center to set it to On.
  2. Main menu → Audiobooks → Series Cover Flow (second row, below Continue) opens it.
  • The setting is Off by default. When it is Off, the Audiobooks menu has no Series Cover Flow row, and Continue groups a book by its album tag.
  • Settings → Menus → Main Menu Items can hide the Audiobooks item of the main menu.
  • The status bar shows Audiobook Series at the top level, and the name of the series inside a series. Below the cover of a book in a series, the name of the series shows.
  • Speed, chapters, the sleep timer and the no-shuffle rule (below) apply to all audiobooks, with the setting On or Off.

How folders become books and series

Classy reads the Audiobooks folder on the internal storage and on the microSD card.

  • An audio file directly in Audiobooks (also an .m4b file) is one book.
  • A folder with no sub-folders and at most one .m4b file is one book. A book never shows its single audio files.
  • A folder with two books or more is a series. In it, each sub-folder is a book, each .m4b file is a book, and the other audio files directly in the folder are together one book, Other.
  • A folder with one book only shows as that book, not as a series of one.
  • A folder that holds only one folder of books is skipped: Audiobooks/Jellyfin/Author/Book (the folders of Jellyfin Sync) shows the series Author. A folder whose only sub-folder holds only files stays one book: Saga/Only Book is the book Only Book.
Audiobooks/
  Long Walk.m4b               a book
  Sea Stories/                a book (files only)
    01.mp3  02.mp3  …
  The Saga/                   a series of three books
    1 First Book/             a book
    2 Second Book/            a book
    Extra.m4b                 a book

The Cover Flow uses the scanned library. After you add or move books, scan again: Main menu → Audiobooks → Scan Media Library (last row).

Sort order

  • Top level: the series that you played last comes first. Then all books and series in alphabetical order (upper and lower case are the same).
  • In a series: the book that you played last comes first. Then the books by the first number in their name (up to 4 digits: Book 2 before Book 10), then alphabetically. Names without a number come after the names with one.
  • The Cover Flow opens on the book or series that you played last.
  • The cover of a series is the cover of its first book (by number, then name), from the first file of that book.
  • In a book: the files play in folder order (Disc 1 before Disc 2), then in natural file-name order (2 before 10, 09 before 10). Track tags do not change the order.

Playback and resume

  • Center on a series opens its books. Center on a book puts all its files in the queue and plays from its saved file and place.
  • Each book remembers its own current file, so it resumes at its chapter also after you played other books. A series remembers the last book that you played in it.
  • A saved place that is not one of the book's files starts the book at its first file.
  • Continue (Main menu → Audiobooks → Continue, first row) plays the last audiobook from its saved place. It uses only files of the Audiobooks folders, so music that you play later never replaces the last audiobook. With the setting On, Continue queues the files of the book (its folder or .m4b), as the Cover Flow does.
  • Shuffle is never used for audiobooks: a book always plays in order.

Speed, chapters and sleep timer

While an audiobook plays, hold the centre button on Now Playing. For an audiobook, the menu shows three rows at the top, above the rows of every song (Queue, Play On and the others). The menu of music does not change.

RowWhat it does
Audiobook Speed1.0x (Normal), 1.2x (Fast), 1.5x (Faster) or 2.0x (Very Fast). The speed is saved and applies to all audiobooks. Music and podcasts keep Settings → Playback → Playback Speed.
ChaptersThe chapters in the .m4b file that plays: a row goes to that chapter. For a book of many files, the files: a row plays that file from its start.
Sleep Timer5, 10, 15, 30, 45, 60, 90 or 120 minutes. At the end, the book pauses, the place is saved, and the player powers off. While it runs, the row shows the time left, and Stop Sleep Timer cancels it.

For developers

  • The setting is Prefs.AUDIOBOOK_SERIES_COVER_FLOW (audiobook_series_cover_flow, default off).
  • The index is controllers/coverflow/AudiobookSeriesIndex.kt: rootEntries, bookEntries, bookFilesOf (Continue), seriesFolderForFile and orderedFiles. It is made from the paths of the scanned library in one pass (it never lists folders on the card) and makes each sort key one time. The screen is ScreenState.AudiobookCoverFlow(seriesDirectory); MainActivityControllers.prepareAudiobookCoverFlow keeps the built indexes for Back and refresh.
  • Saved places in the app prefs: book_pos_<path> (position in a file), audiobook_last_in_<folder> (current file of each folder above it), audiobook_series_last_book_<series>, audiobook_series_last_played, last_played_audiobook_path and audiobook_speed.
  • Tests: app/src/test/java/com/themoon/y1/controllers/AudiobookSeriesIndexTest.kt.
